THE HARDWARE COST,
WITHOUT THE HAND-WAVING.

For most first builds the honest number is $0, because the machine is already on the desk. Here is what a GPU actually buys you, what recurring costs are real, and how to run the comparison fairly.

By the Marapone team · Updated 2026

The phrase “runs on your own hardware” does a lot of work in AI marketing, and it usually hides a GPU purchase. So it is worth writing down what a private construction AI actually costs to run, including the cases where the answer is genuinely zero because the machine is already on the desk.

The short version: for one user, the hardware requirement is a business laptop bought in the last few years. The interesting question is not the minimum — it is what you gain by spending more, and where that curve flattens.

The floor is lower than people expect

A single-user install wants four modern cores, 16 GB of RAM and about 20 GB of free SSD. No GPU. That is a mid-range MacBook Air, a Dell Latitude from the last refresh cycle, or the workstation your estimator already has.

The reason the floor is that low is that document work is not the same computational problem as training a model or generating video. Extraction, comparison and structured reasoning over a few hundred pages is a workload a CPU handles fine. It is not instant — a large plan set takes minutes rather than seconds — but minutes against a manual baseline of hours is not the bottleneck in anyone’s day.

The honest number for most first builds:

$0 in additional hardware. The machine exists, and the software installs onto it like any other application.

What a GPU actually buys

A GPU changes throughput, not capability. The same documents produce the same findings; they produce them faster, and more of them at once. That matters in exactly two situations:

Several people running work simultaneously. One shared machine serving a buyout week where three coordinators are all pushing packages through it.

Very large sets processed in a batch. A full tender package with hundreds of sheets, where the difference between twenty minutes and four is the difference between a coffee and a lunch.

If neither describes you, the GPU is a purchase that buys you a shorter progress bar. That is a real thing to want, but it should be an explicit decision rather than an assumed requirement.

The three tiers, with real prices

Tier Spec Hardware cost Suits
Existing machine 4 cores, 16 GB RAM, 20 GB free. No GPU. $0 One estimator or PM. The common case.
Dedicated workstation 8 cores, 32 GB RAM, optional 8 GB+ VRAM GPU. ~$3–5k Daily heavy use, or a machine that is not someone’s laptop.
Office server 8–16 cores, 64 GB+, 16–24 GB VRAM, NVMe sized to your archive. ~$15–25k A 10–50 person shop running it as shared infrastructure.

Most shops that think they need the third tier are better served starting at the first, running real work through it for a month, and buying hardware against measured demand rather than projected demand. The install moves between machines; nothing is tied to the metal.

The costs nobody quotes

Electricity. A workstation under sustained load is a space heater you already own. At Toronto commercial rates, a machine running several hours a day is somewhere in the low tens of dollars a month. It is a rounding error against a single billable hour, but it is not zero and it is the only true recurring cost.

Storage growth. Document archives grow. Plan sets are large. Budget disk against a few years of projects rather than against the first one, because running out is annoying rather than expensive.

Backup. The system runs on your machine, which means the resilience of your data is now your responsibility rather than a vendor’s. If that machine is not already in a backup routine, put it in one. This is the single most commonly skipped step, and it is the one that actually hurts.

One day, every few years. An OS upgrade or a dependency refresh, the same as for any other application you run in-house.

How to compare it honestly against a subscription

The comparison people reach for is licence cost versus build cost, which understates both sides. The fair version puts everything in:

Rented: per-seat fees × seats × 36 months, plus the increases you should assume rather than hope against, plus the cost of the migration you would face if you left.

Owned: the one-time build, plus hardware if any, plus electricity, plus a realistic allowance for a maintenance day every couple of years, plus whatever changes you expect to commission.

Run that over three years with your actual seat count. The answer genuinely depends on the seat count — for one or two users a subscription can win, and we would rather you found that out from arithmetic than from us. The owned model pulls ahead as the number of people using it grows, because nothing about the cost scales with seats.

The practical recommendation

Start on the machine you already have. Run real documents through it for a few weeks. If it is fast enough — and for a single user it almost always is — you have your answer and your hardware budget was zero.

If it is not, you will by then know exactly which part is slow and how much throughput you actually need, which is a much better basis for a purchase than a specification sheet written before anyone tried it.
